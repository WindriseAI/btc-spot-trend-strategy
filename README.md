# BTC 现货趋势策略（OKX）

> **⚠️ 免责声明：本项目不是投资建议，盈亏自负。**
> 请只使用亏掉也不影响正常生活的资金。历史回测不代表未来收益。

这个程序每天看一次比特币（BTC-USDT）的日线走势，按固定规则算出「现在应该拿几成比特币」，然后在你自己的欧易（OKX）**现货**账户里调到目标比例。

- 只做现货、只做多、不加杠杆、不做空。程序里**没有**提现、划转、借币、合约的代码。
- 每天最多下一笔单。重复运行、中途崩溃都不会多下。

---

## 一、风险说明与合理预期（请先读完）

这套规则的目标是**少亏**，不是多赚。

| 你可以期待的 | 你必须接受的 |
|---|---|
| 大跌时仓位很低甚至空仓，账面亏损比一直拿着小得多 | 长期年化大约 10–20%（不是历史回测里的 23–25%）|
| 熊市里不用自己做决定 | 任意 3 年亏钱的可能约 1/4 到 1/3 |
| | 账面回撤可能到 -45% ~ -50% |
| | 可能连续两三年不创新高（回测里最长约 2 年 8 个月）|
| | 行情 V 型反转时会晚上车；大牛市里比一直拿着赚得少 |

和「每月定投、一直拿着」比（110U 起步、每月存 50U、拿 3 年，回测了 95 个不同起点）：定投最后的钱更多（中位数是投入的 2.1 倍，这套规则 1.7 倍），但中途最深要扛 -58% 的账面亏损；这套规则中途最深约 -19%。**如果你能扛住 -60% 不割肉，定投更简单也更赚。** 选这套规则，是为了跌的时候拿得住。

详细数字见 [docs/backtest-report.md](docs/backtest-report.md)（开头有一页结论），完整上手教程另见 [docs/给用户的说明.md](docs/给用户的说明.md)。

## 二、AI Builder Code 说明

- 本程序支持在通过欧易（OKX）官方 OpenAPI 下单时，携带作者的欧易 **AI Builder Code**（通过环境变量 `OKX_AI_BUILDER_CODE` 配置，写入订单的 `tag` 字段，1–16 位英文字母或数字）。
- 订单携带该 Builder Code 时，**作者会因此获得欧易官方的手续费返佣**；**用户的交易手续费不会因此增加**。
- **作者不接触、不收集、不保存你的任何 API key**。密钥仅保存在你自己的本机 `.env` 或环境变量中，程序直接请求欧易官方接口。

## 三、规则（程序就是照这个做的）

每天 UTC 0 点（北京时间早上 8 点）日线收盘后：

1. **趋势**：看今天的收盘价比 20、40、60、90、120、180、240 天前高还是低。高的算「上涨」，其余算「下跌」。
   E = max(0, 上涨个数 − 0.3 × 下跌个数) ÷ 7。
   上涨 0～7 个时，E 分别是 0、0、0.07、0.26、0.44、0.63、0.81、1。
2. **波动率**：最近 30 天的年化波动率 vol30。V = min(1, 40% ÷ vol30)。波动越大，拿得越少。
3. **目标仓位** T = E × V（0 到 1 之间）＝ 账户里应该有几成是比特币。
4. **调仓门槛**：只有目标仓位和实际仓位相差达到 20 个百分点才动；目标是 0 时不管差多少都全部卖出。
5. **新存进来的钱**：直接算进账户总值，下次按 T 分配。
6. **不抄底**：价格跌了不会因此加仓，只有 T 变大才会买。
7. **熔断**：账户净值（扣除存取款的影响）从最高点跌 45% → 全部卖成 USDT，暂停 30 天并报警；之后按半仓运行，直到你本人确认恢复，或半仓满 12 个月自动恢复。

> 第 1 条里的「− 0.3 × 下跌个数」是当前默认采用的新权重；原来的写法（上涨个数 ÷ 7）作为「影子账」并行记录，周报里会对比。
> 复核结果（2018 年至今）：新权重让历史最大回撤从 36–38% 降到 28–32%，**收益基本没变**（年化约 22–26%，新旧相差不到 2 个点）。它是「拿得更少、跌得更浅」，不是「又多赚又少亏」。详见 [docs/backtest-report.md](docs/backtest-report.md) 第 3 节。

## 四、第一次设置（约 20 分钟）

### 1. 安装

电脑上需要 Python 3.10 或更新版本。在项目根目录打开终端：

```bash
pip install -r requirements.txt
```

### 2. 不用任何密钥，先看一眼今天的信号

```bash
python -m btc report
```

会打印一份中文日报。这一步不需要账号、不会下单。

### 3. 创建「模拟盘」API key（先用假钱练）

1. 登录欧易网页版 → 顶部「交易」→「模拟交易」（Demo Trading）。
2. 在模拟交易界面，点右上角头像 →「模拟交易 API」→「创建模拟盘 API key」。
3. 权限只勾 **读取** 和 **交易**。**不要勾提现**。
4. 自己设一个 Passphrase（口令），记下来。
5. 创建后会显示 API key 和 Secret key（Secret 只显示一次），连同口令一共三样。

### 4. 把密钥放进 `.env` 文件

把 `.env.example` 复制一份，改名为 `.env`，填上：

```dotenv
OKX_DEMO_API_KEY=你的模拟盘 API key
OKX_DEMO_API_SECRET=你的模拟盘 Secret
OKX_DEMO_API_PASSPHRASE=你的口令

# 可选：作者的欧易 AI Builder Code（不增加你的手续费）
OKX_AI_BUILDER_CODE=
```

`.env` 只留在你自己的电脑或运行环境里。**不要发到聊天里，不要发给任何人。** 这个文件已被设置为不会进入 git。

### 5. 跑模拟盘

```bash
python -m btc paper
```

它会在欧易模拟盘上真实下单（用的是模拟资金）。建议每天跑一次，连续跑 2～4 周，确认日报、周报、下单都正常。

> 模拟盘账户里欧易会预先放一大笔假币（几个 BTC、几万 USDT），所以金额看起来很大，这是正常的，只是用来验证流程。

### 6. 上实盘前的检查清单

- [ ] 模拟盘连续运行至少 2 周，日报没有持续的「错误」「没有下单」。
- [ ] **确认该交易账户里没有任何未平仓的合约或杠杆持仓。** 只要账户里还有任何合约、杠杆持仓或借币，程序就拒绝做现货买卖（它也绝不会去碰合约）。强烈建议使用专门的欧易**子账户**运行本策略。
- [ ] 钱在欧易的**交易账户**里（充值默认进「资金账户」，需要在 App 里划转到「交易账户」）。
- [ ] 交易账户里所有的 BTC 和 USDT 都会被当成这套策略的本金。不想让它管的钱，放在资金账户或其他子账户。
- [ ] 在欧易 App 或网页的「手续费率」页面看一下自己的现货手续费率。普通用户一般是吃单 0.1%；如果你看到的是 0.2% 或 0.35%，在 `.env` 里加一行 `SPOT_FEE=0.002`（或 `0.0035`）。

### 7. 创建「实盘」API key

1. 欧易网页版（**不是**模拟交易界面）→ 右上角头像 →「API」→「创建 API key」。
2. 权限只勾 **读取** 和 **交易**。**绝对不要勾提现**——程序发现 key 带提现权限会直接拒绝运行。
3. **绑定 IP 地址**：填运行这个程序的那台机器的公网 IP。不绑 IP 的话，key 连续 14 天不用会被欧易自动作废，而且不安全。
4. 在 `.env` 里填：

```dotenv
OKX_API_KEY=实盘 API key
OKX_API_SECRET=实盘 Secret
OKX_API_PASSPHRASE=实盘口令
LIVE_CONFIRM=yes
```

`LIVE_CONFIRM=yes` 是实盘的总开关。没有这一行，`python -m btc live` 不会运行。

### 8. 跑实盘

```bash
python -m btc live
```

## 五、每天怎么运行

| 命令 | 作用 | 会下单吗 |
|---|---|---|
| `python -m btc report` | 今天的信号 + 按规则该做什么 | 不会 |
| `python -m btc paper` | 模拟盘：算信号并在模拟盘下单 | 模拟资金 |
| `python -m btc live` | 实盘：算信号并下单 | **真钱** |
| `python -m btc weekly` | 周报（最近 7 天信号 + 四本账对比）| 不会 |
| `python -m btc confirm-resume live` | 熔断暂停期结束后，由你确认恢复正常仓位 | 不会 |

- 建议时间：每天**北京时间 08:22**（UTC 00:22），日线收盘后 22 分钟。晚几个小时再跑没关系（回测里收盘后 0～12 小时内成交差别很小），但不要习惯性拖到第二天。
- 一天跑多次没问题：同一天只会下一笔单，之后再跑只是重新出报告。
- 某天没跑也没关系，第二天照常跑。不需要补。
- 每条命令都只在屏幕上打印一份纯文字报告；正常时退出码是 0，需要人看一眼时是 1。

## 六、日报怎么看

```text
【BTC 策略日报】2026-11-21（北京时间 08:22）｜实盘
BTC 收盘价（UTC 11-20）：58,952.70
趋势：0/7 个回看期上涨（上涨：无；下跌：20、40、60、90、120、180、240 日）→ E = 0.00
波动率 vol30：45.1% → V = 0.89
目标仓位 T = E×V：0%
当前仓位：0%（BTC 0.00000000，USDT 120.00）
操作：无需操作 —— 目标仓位是 0，现在已经空仓（全部是 USDT）
账户净值：120.00 USDT｜距最高点回撤：0.0%
熔断：正常（回撤达 45% 才触发，现在 0.0%）
数据：OKX，已用 Binance 交叉核对（最新收盘相差 0.00%）
错误：无
```

| 这一行 | 意思 |
|---|---|
| 趋势 | 7 个回看期里几个在涨。个数越多，E 越大 |
| 波动率 / V | 最近波动大，V 就小于 1，仓位打折 |
| 目标仓位 T | 按规则现在该拿几成比特币 |
| 当前仓位 | 账户里实际是几成 |
| 操作 | 「无需操作」（差距没到 20 个点，或已经空仓）／「已买入…」／「已卖出…」／「⚠️ 没有下单 ——（原因）」|
| 账户净值 / 回撤 | 交易账户里 BTC + USDT 的总值；回撤是扣除存取款影响后，从最高点跌了多少 |
| 熔断 | 正常 / 今天触发 / 暂停中 / 半仓运行 |
| 数据 | 价格来自哪里、有没有核对过 |
| 错误 | 「无」就没事。标题前面有 ⚠️ 说明需要你看一眼 |

**周报**多出「四本账对比」：同样的本金和存款，如果用另外三种办法（旧权重、存入就买一直拿着、一半 BTC 一半 USDT）现在各值多少。还有一行「实盘与规则重放的偏差」——超过 2% 说明执行出了问题（漏跑、订单失败等），要查。

## 七、怎么停下来

从轻到重：

1. **只想暂停下单**：把 `.env` 里的 `LIVE_CONFIRM=yes` 改成 `LIVE_CONFIRM=no`，或者把定时任务改为只跑 `python -m btc report`。
2. **彻底切断**：在欧易网页版 → API → 删除那个 API key。删掉之后任何程序都动不了你的账户。
3. 程序不会自动卖出你的比特币（除非规则算出目标仓位是 0，或触发熔断）。停掉程序后，手里的币要不要卖由你自己决定。

## 八、程序自带的保险

- 只会对 `BTC-USDT` 现货下「立即成交、带价格上限」的限价单（价格最多比盘口差 0.3%，超出就不成交）。选这种单而不是市价单，是因为中小额订单会立刻按盘口成交，而价格上限能挡住极端瞬间的滑点；也不用挂单等待，程序跑完就结束，不会留下没人管的挂单。
- 买入金额不会超过账户里的 USDT，卖出数量不会超过手里的 BTC：不可能借钱、不可能做空。
- API key 带提现权限 → 拒绝运行。
- 账户里有合约/杠杆持仓或借币 → 不做现货买卖，并在日报里提醒。
- 行情数据过期、缺失，或两个数据源对不上（最新收盘价相差超过 1.5%，或算出的目标仓位差 20 个点以上）→ 当天不下单，并在日报里说明。
- 实盘必须有 `LIVE_CONFIRM=yes`。
- 状态文件（`state/` 目录）记录最高净值、存取款、熔断状态和每天的记录。它每次都是完整写入并保留上一版备份；如果损坏，程序会拒绝交易而不是从头再来。**`state/` 目录不能删，也不能每次运行都换新的。**
- 密钥只从环境变量或 `.env` 读取，不会打印、不会写进日志或状态文件。

## 九、请不要做的事

- 不要在交易账户里手动买卖 BTC——下次运行程序会按规则调回去，你的操作白交手续费。想加钱就直接充值并划转到交易账户，程序会自动识别为入金。
- 不要因为「这周亏了」就改参数。判断这套规则好不好，至少要看满一轮牛熊（约 3 年）。
- 不要把熔断线调紧（回测里调到 25%–35% 反而更差）。
- 不要把 `.env` 或 API key 发给任何人。
